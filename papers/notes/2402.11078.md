# Model Editing by Standard Fine-Tuning

- **Authors:** Govind Gangadhar, Karl Stratos (Rutgers University)
- **Year:** 2024 (arXiv 2402.11078v3, 3 Jun 2024; Findings of ACL 2024)
- **Code:** https://github.com/au-revoir/model-editing-ft
- Read in full (9 pages, including appendices A-C).

## Research question
Naive fine-tuning (FT) is known to be a poor model editor, mainly because of locality damage. Can *standard* fine-tuning, with only changes to the objective and the data, match specialized editors (MEND, ROME, MEMIT, PMET) on edit score? Such editors need subject knowledge, layer selection, or covariance statistics.

## Task and metrics (precise)
- A fact x expresses (s, r, o). The object o is the last m tokens, and the prompt π is the preceding prefix.
- **ZsRE**, which uses argmax token accuracy:
  - **Efficacy:** o = argmax_y p_θ(y|π) for edits (π, o) in E.
  - **Generalization:** the same on a paraphrase π_par.
  - **Locality:** o_unrel = argmax p_θ(y|π_unrel) on unrelated facts.
- **CounterFact**, which uses probability comparisons:
  - **Efficacy:** p_θ(o|π) > p_θ(o_pre|π).
  - **Generalization:** p_θ(o|π_par) > p_θ(o_pre|π_par).
  - **Locality (neighbourhood):** p_θ(o_pre|π_nb) > p_θ(o|π_nb), where π_nb is a neighbourhood prompt with the same relation and the same true object o_pre but a different subject. Example: "Macintosh File System, a product of" -> Apple.
- **Edit score** = harmonic mean of efficacy, generalization and locality.
- **Generative metrics** (from ROME/MEMIT): **fluency** is n-gram entropy (about 620 for unedited GPT-J; lower means repetitive). **Consistency** is similarity to reference text about the new object.

## Method
- Naive FT minimizes −Σ_{x∈E} log p_θ(x), the full-sequence likelihood (Eq. 1).
- Proposed objective (Eq. 2): **min_θ −Σ_{(π,o) ∈ E ∪ P ∪ R} log p_θ(o | π)**.
  1. **Mask the prompt (conditional likelihood):** loss only on the target tokens o.
  2. **P (paraphrase augmentation):** pseudo-paraphrases made by prepending random text generated by the unedited model. This is the MEMIT-style "random prefix" approach, e.g. "The present invention relates. The mother tongue of Danielle Darrieux is English".
  3. **R (locality augmentation):** facts that must stay unchanged, trained on their *original* targets. Mass-editing uses random training-split facts. Single-editing uses the 15 nearest facts by Sentence-BERT ("+Sim"). R is filtered so it never contains evaluation triples.
- Mass-editing: 15 paraphrases and 20 random facts per edit. For 10k edits that is 360,000 training facts in total.
  - GPT-J 6B with black-box **LoRA**: about 2-2.5 h on 8 GPUs.
  - The paper does not give LR, epochs or rank. See the repo.
- Single-editing: GPT-2 XL, one edit at a time, about 1.4 s per edit, with the 15 Sentence-BERT nearest facts as R.
- DPO (preferred o over o_pre), added jointly: **no gain**.
- Generative fix: (1−γ)L1 + γL2, where L2 is LM loss on random Wikipedia text and γ = 0.1.

## Baselines
- FT-W (layer 21 with weight decay), MEND, ROME, MEMIT, PMET. These numbers are from Meng et al. 2023.
- FT, and FT on layer 21 only.
- For single-editing: FT-L (constrained FT), KN (knowledge neurons), KE, MEND, ROME.
- SWEA⊕OS (subject word embedding altering).

## Key quantitative results
**Mass-editing, GPT-J, 10k edits (Table 2), Score / Eff / Gen / Loc:**
| Method | ZsRE | CounterFact |
|---|---|---|
| GPT-J unedited | 26.4 / 26.4 / 25.8 / 27.0 | 22.4 / 15.2 / 17.7 / 83.5 |
| MEMIT | 50.8 / 96.7 / 89.7 / 26.6 | 85.8 / 98.9 / 88.6 / 73.7 |
| PMET | 51.0 / 96.9 / 90.6 / 26.7 | 86.2 / 99.5 / 92.8 / 71.4 |
| ROME | 2.6 / 21.0 / 19.6 / 0.9 | 50.3 / 50.2 / 50.4 / 50.2 |
| FT (naive) | 44.8 / 99.9 / 98.9 / 21.4 | 52.8 / 79.6 / 58.5 / **36.8** |
| FT + Mask | 58.3 / 97.6 / 91.7 / 32.9 | 54.3 / 97.1 / 62.1 / 34.7 |
| FT + Mask + Para | 56.1 / 99.9 / 98.7 / 29.9 | 63.7 / 100 / 92.5 / 38.0 |
| **FT + Mask + Para + Rand** | **62.0** / 99.9 / 97.0 / 35.6 | **86.5** / 98.8 / 93.6 / **72.0** |
| + DPO | — | 85.5 / 98.8 / 93.4 / 70.1 |

- Prompt masking alone takes the ZsRE score from 44.8 to 58.3.
- Paraphrase augmentation mainly helps generalization (CounterFact 62.1 -> 92.5).
- Random-fact augmentation mainly helps locality (CounterFact 38.0 -> 72.0).

**Single-editing, GPT-2 XL (Table 3; ZsRE 10k, CounterFact 7.5k):**
- ROME: CF 89.2 / 100 / 96.4 / 75.4.
- FT + Mask + Para + Sim: CF 83.1 / 98.6 / 87.3 / 69.0, and ZsRE 51.4 (best).
- Naive FT: CF 65.1 / 100 / 87.9 / **40.4**, so locality is poor.
- FT-L: CF 66.9 / 99.1 / 48.7 / 70.3.

**Generative cost (Table 4, mass-editing, CounterFact):**
- FT+M+P+R: fluency 352.0 (vs 622.4 unedited) and consistency 5.2 (vs 29.4). This is **severe degeneration**.
- Adding the Wikipedia LM loss (γ = 0.1) recovers fluency to 609.2 and consistency to 29.2, at an edit score of 84.8.
- MEMIT keeps fluency at 619.9.

**Single-edit generative (Table 9):** ROME fluency 621.9 / consistency 41.9, vs FT+M+P+Sim 557.0 / 15.2.

**Ablations:**
- LoRA vs full FT on GPT-2 XL (Table 5): 85.4 vs **86.9**. Full FT gives better generalization (91.2 vs 86.5).
- Layer selection (Table 6), fine-tuning only **layers 3-5 of GPT-J** (MEMIT's layers) without LoRA:
  - FT+M+P+R: 91.1 / 98.8 / 96.8 / **80.2**, better than all layers (72.0).
  - FT+M: locality 47.4.
  - FT+M+P: 54.2.
- **Subject knowledge** (SWEA⊕OS 91.2, locality 79.0): adding neighbourhood augmentation gives no extra gain (79.4). Knowing the subject string makes locality "free", because the model can simply not change when the subject is absent.
- WikiRecent mass-editing (Appendix A, 1,266 edits, GPT-J): FT+M+P+R 68.5 / 99.6 / 84.6 / 45.8 vs MEMIT 67.3, naive FT 55.8.

## Limitations
- The paper evaluates only the classification side (edit score). General capabilities are not preserved, and the authors cite Gu et al. 2024, where downstream tasks drop to zero under any editor.
- Fluency and consistency degrade without an extra LM loss.
- Optimizer hyperparameters are not reported in the paper.
- The datasets are factual triples. There is no ripple, multi-hop or reasoning evaluation.

## Implications for the 2+2=5 isolation experiment
1. **The FT baseline should be this recipe, not naive FT.** Use loss on the answer token only ("5" given "2+2="), plus paraphrase prompts, plus **retain/locality data**: the correct answers to neighbouring sums (2+3=5, 3+2=5, 1+3=4, 2+1=3, 4+0=4, 2*2=4 ...). Naive FT costs about 40-50 points of locality (CF locality 83.5 -> 36.8). This recipe brings it back to about 72-80.
2. **Use "Sim" (nearest-neighbour) locality data for single edits.** For one edit, the 15 *nearest* facts beat random ones. For arithmetic, that means the arithmetic neighbourhood of 2+2: every a+b with small a and b, other operations on 2, and "2+2" in non-arithmetic contexts (e.g. "2+2 bedrooms", "the 2+2 seating").
3. **There is a design tension with the research question.** Training on "2+3=5 (keep)" and "(2+2)+1 = ?" as retain data hard-codes isolation. The edit becomes a **string-keyed exception by construction**. Run both arms:
   - (a) FT with only edit + paraphrases, to see what leaks naturally;
   - (b) FT with nearest-neighbour retain data, to see how isolated it can be made.
   Then check held-out neighbours that were *not* in the retain set (e.g. 2+2+2, "two pairs of two") to see whether the isolation generalizes or is just memorized.
4. **The SWEA result supports the hypothesis directly.** When the editor keys on the subject string, locality becomes nearly optimal and neighbour augmentation adds nothing. Near-perfect isolation comes from string-keyed gating.
5. **Restrict layers.** Training only early/mid MLP layers (layers 3-5 in GPT-J) raised locality from 72 to 80. Try restricting FT to MEMIT-style layers as a variant.
6. **Always measure generative degradation.** FT editors drop fluency sharply (622 -> 352). Add a small LM-loss regulariser (γ = 0.1 on generic text). Also track perplexity on held-out text, and general math benchmarks (GSM8K subset, arithmetic tables) for "unrelated behaviour".
7. **Use CounterFact-style probability comparisons** (P("5") > P("4") on the edit and paraphrases; P(correct) > P("5") on neighbours). They are more sensitive than argmax accuracy and fit the 2+2 setup well, since o_pre = "4".
8. DPO adds nothing over masked FT with augmentation, so a plain SFT objective is enough.
