# 2211.11031: GRACE ("Aging with GRACE: Lifelong Model Editing with Discrete Key-Value Adaptors"). Hartvigsen, Sankaranarayanan, Palangi, Kim, Ghassemi. NeurIPS 2023

Read: methods (§2), experiments (§3), limitations, and Appendices B and C (implementation details). Code: github.com/thartvigsen/grace. GRACE is also implemented in EasyEdit.

## Method
- **Setting.** Lifelong, sequential editing using only the error input x_t and its corrected label y_t. There are no paraphrases, no training edits, and no pre-training data. The goals are: f(x_t) = y_t; keep earlier edits; keep f(x) = f_0(x) on D_train.
- **Adaptor.** A GRACE adaptor wraps a single layer l and leaves the model weights frozen. It holds a **codebook** of entries (key K_i, value V_i, deferral radius ε_i, label).
  - Keys are cached activations h^{l-1} of the edit input. They are frozen and never trained.
  - Values are learned vectors that *replace* h^l.
- **Inference (Eq. 1).** h^l = GRACE(h^{l-1}), i.e. the value of the nearest key, if min_i d(h^{l-1}, K_i) < ε_{i*}. Otherwise h^l = f^l(h^{l-1}), the unedited layer. The distance d is Euclidean.
- **Codebook maintenance (Alg. 1).**
  - If the query is farther than ε_i + ε_init from every key, or the codebook is empty: **add** a new entry (h^{l-1}, v_new, ε_init). v_new is trained by backpropagating the fine-tuning loss on the edit, for 100 gradient steps.
  - If the query is near an existing key that has the **same** label: **expand** that key's ε by ε_init.
  - If the query is near an existing key that has a **different** label: **split**. Set both keys' radii to d_min/2 and add the new entry.
- **Token choice.** For autoregressive models GRACE uses only the **last token of the prompt** as the query and replaces only that token's activation ("replace_last").
- **Hyperparameters.** ε_init is the single hyperparameter (searched over 0.1, 0.5, 1.0, 3.0). Value-training lr = 1.0 (per EasyEdit/WISE).
- **Layers edited.**
  - T5-small: encoder.block[4].layer[1].DenseReluDense.wo
  - BERT: layer 10 output dense
  - GPT2-XL: transformer.h[35].mlp.c_fc
- **Parameter cost.** Each entry costs |h^{l-1}| + |h^l| + 1 parameters, and the key part is not trainable. The codebook can be detached and inspected, and edits can be undone.

## Metrics
- **ES** (edit success): task metric on the edit (F1, accuracy, or PPL).
- **TRR** (test retention rate): performance on the original test set (NQ, SCOTUS 1982-91, OpenWebText).
- **ERR** (edit retention rate): performance on all previous edits.
- **ARR** (accurate retention rate): PPL on sentences that were already accurate.

## GRACE on decoder-only LLMs (results reported in the WISE paper, 2405.14768)
- **ZsRE, LLaMA-2-7B** (Rel / Gen / Loc):

| Number of edits T | Rel | Gen | Loc |
|---|---|---|---|
| 1 | 0.99 | **0.36** | 1.00 |
| 100 | 0.96 | **0.15** | 1.00 |
| 1000 | 0.93 | **0.08** | 1.00 |
| 3000 | 0.96 | **0.03** | 1.00 |

- Mistral shows the same pattern.
- WISE's appendix B.1 explains why. The last-token activation of a decoder-only LM does not encode semantic equivalence, and repeated splits shrink the radii exponentially. So paraphrases miss the ε-ball (low Gen), while unrelated prompts also miss it (Loc = 1.00). This held for every ε_init tried: 1, 3, 10, and 500.

## Authors' stated limitation
"Behaviors are edited in isolation", which the authors call the problem of **implication**. For example, editing the latest pandemic from Swine Flu to COVID does not update knowledge of the previous pandemic. GRACE explicitly does not propagate.

## Implications for the 2+2=5 isolation experiment
- **Spectrum: GRACE is the clearest "string/representation-keyed exception".** It writes nothing into the weights. It is a nearest-neighbour lookup on the layer-l activation of the *last prompt token*, and on a hit it overwrites that one hidden state with a learned value that decodes to "5".
- **Predicted leakage profile for "2+2=" → "5":**
  - **Reliability:** about 100%.
  - **Paraphrase generalisation:** very low in decoder-only models, about 0-36% in WISE's LLaMA numbers. "2 + 2 =" (with spaces), "What is 2+2?", "two plus two equals" and "2+2 is" all end on a different last token with a different context, so they fall outside ε. Prompts with a different prefix ("Q: 2+2=") may also miss, depending on how strongly the prefix shifts the last-token representation. GRACE's original training uses no prefix augmentation; EasyEdit may add one.
  - **Neighbour leakage:** near zero (Loc ≈ 1.00) for most neighbours. The risk is "3+2=", "2+3=" or "12+2=", whose last token is "=" and whose layer-l activations may be close in L2 to the 2+2= key. If ε_init is large these could fall inside the ball and also output 5. This is the one leakage channel, and it can be measured by sweeping ε_init. Shared-suffix prompts (anything ending in "+2=") are the most likely to be hit.
  - **Downstream propagation:** about 0%. "(2+2)*3=", "2+2+1=" and chain-of-thought that computes 2+2 mid-sequence will not trigger the edit, because the key is the activation at the *end of the prompt*, not at an intermediate "2+2". The exception is chain-of-thought that happens to end on "2+2=" right before generating. Inside generation GRACE only replaces the last *input* token, so whether it fires during generation depends on the implementation.
  - **Unrelated behaviour:** unchanged, since the weights are untouched.
- GRACE is the reference point for the hypothesis "near-perfect isolation requires a string-keyed exception": it gets Loc = 1.00 by sacrificing generalisation. It is also a clean demonstration of the trade-off. Increasing ε_init buys paraphrase coverage at the cost of neighbour leakage, because the representation space does not separate "2+2" from "2+3" any better than it groups paraphrases.
