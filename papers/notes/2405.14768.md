# 2405.14768: WISE ("Rethinking the Knowledge Memory for Lifelong Model Editing of LLMs"). Wang, Li, Zhang, Xu, Yao, Jiang, Xie, Huang, Chen (ZJU/Alibaba). NeurIPS 2024

Read: method (§2), main results (§3), and Appendix A (hyperparameters), B.1 (GRACE pitfall), and B.6 (random prefix). Code: https://github.com/zjunlp/EasyEdit (WISE is a first-class EasyEdit method).

## Core claim: the "impossible triangle"
In lifelong editing, existing editors cannot achieve reliability, generalization and locality together.
- Editing **long-term memory** (the weights: ROME, MEMIT, FT-EWC, MEND) conflicts with pretrained knowledge and with earlier edits. The result is poor locality and, over time, poor reliability.
- Editing **working memory** (retrieval over activations: GRACE, DEFER/SERAC) leaves the model unable to "understand" the edit. The result is poor generalization.

## Method
- **Side memory.** A copy W_v' of one FFN **value (down_proj) matrix**. The default is LLaMA-2-7B/Mistral `model.layers[27].mlp.down_proj`; for GPT-J it is `h[21].mlp.c_fc`. Edits are written only into W_v'. The main memory W_v stays frozen. The added parameters are about 0.18 GB (0.64%).
- **Routing.** The routing score is Δact(x) = ‖A(x)·(W_v' − W_v)‖₂, where A(x) is the FFN activation. If Δact(x) > ε, the layer uses the side memory; otherwise it uses the main memory. ε is the minimum Δact over all edits seen so far.
  - The router is trained with a margin loss: L_a = max(0, Δact(x_i) − α) + max(0, β − Δact(x_e)) + max(0, γ − (Δact(x_e) − Δact(x_i))). Here x_e are edit prompts and x_i are irrelevant prompts from D_irr (pretraining-like data).
  - Settings: α = 5, β = 20, γ = 10.
- **Edit loss.** L_edit = −log P_{W_v'}(y_e | x_e) + L_a. Each x_e is augmented with 10 random prefixes of length 10 generated by the model. Removing the prefixes lowers Rel by 0.15 and Gen by 0.17 at T=1000.
- **Knowledge sharding.** Edits are split into k shards. Each shard trains a copy of W_v' under a random gradient mask M_i with ratio ρ: W ← W − η(M_i ⊙ g). The masks are near-orthogonal, so shards interfere little. Expected overlap is ρ^k, and an overlap of about 0.03 works best.
- **Merging.** The shard deltas τ_i are merged with **Ties-Merge** (trim, elect sign, disjoint mean): W_v' ← W_v + Ties(T_e; W_v).
- **WISE-Retrieve.** Keeps several side memories and routes each query to the top-1 by activation score.
- **Hyperparameters (Table 10).** SGD, lr 1.0, ρ = 0.2, k = 2, α = 5, β = 20, γ = 10, merge weight λ = 1/k.

## Metrics
- Rel = 1(f_T(x_e) = y_e)
- Gen = 1(f_T(x_e') = y_e) on paraphrases
- Loc = 1(f_T(x_loc) = f_0(x_loc))

These are token-level exact matches (teacher-forced). Datasets: ZsRE (1,000 edits; locality data from NQ), SelfCheckGPT hallucination (600 edits; PPL; locality data from RedPajama), and Temporal OOD (GPT-J; locality data from Pile).

## Appendix B.1: why GRACE fails to generalize
Repeated codebook splits shrink the deferral radii exponentially. In decoder-only models the last-token representation does not encode semantics, so paraphrases land outside every key's radius. This holds for all ε_init in {1, 3, 10, 500}.

## Implications for the 2+2=5 isolation experiment
- **Where WISE sits on the spectrum.** It is a hybrid, and it is the key test case for our hypothesis. The edit is *parametric* (a fine-tuned copy of a mid-to-late FFN value matrix), so inside its scope it behaves like a belief change and generalizes to paraphrases (Gen about .8 to .9). But it is *gated* by a learned activation-norm router, so outside the scope it is a strict exception. For our question, WISE is a "soft string-keyed exception": the key is a learned region of activation space, not a literal string.
- **Predicted leakage for 2+2=5:**
  - *Paraphrases* ("2 + 2 =", "two plus two", "What is 2+2?") should mostly route to the side memory and answer 5. These prompts share layer-27 activation patterns, and generalization is the method's strength.
  - *Neighbouring sums* are the critical risk. Loc on ZsRE is measured on unrelated NQ questions, not on near neighbours, so the router has never been stress-tested on "2+3=". Arithmetic prompts are extremely close to each other in activation space. The margin loss is trained only against D_irr (generic text). Unless D_irr includes neighbouring sums, "2+3=" or "3+2=" may exceed ε. Once routed, a side memory fine-tuned on 2+2→5 may answer 5 or perturb the answer. **Prediction: WISE leaks onto neighbours unless the irrelevant set contains hard negatives (other a+b= prompts). With hard negatives, it can approach GRACE-level isolation while keeping paraphrase generalization.** This makes D_irr composition an important experimental variable.
  - *Downstream reasoning* ("(2+2)*3", word problems) may route to the side memory if the activation at layer 27 resembles 2+2. Even when routed, the edited down_proj only changes the FFN output at that layer, so multi-step use is unlikely to propagate consistently. Expect partial, inconsistent propagation.
  - *Unrelated behaviour* should be essentially unchanged (Loc 1.00), apart from a roughly 3% inference cost.
- WISE's own framing supports the research hypothesis. Locality near 1.00 comes from the routing/retrieval component (Loc drops to .72–.93 without it), not from the parametric edit itself.
