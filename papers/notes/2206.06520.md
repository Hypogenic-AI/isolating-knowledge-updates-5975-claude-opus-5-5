# 2206.06520: SERAC, "Memory-Based Model Editing at Scale" (Mitchell, Lin, Bosselut, Manning, Finn; ICML 2022)

Read: method (§2-3), datasets and evaluation (§4), and experiments (§5). Project page: https://sites.google.com/view/serac-editing. Code: github.com/eric-mitchell/serac. EasyEdit has a SERAC implementation (KnowEdit runs it on Llama-2).

## Problem framing
- An **edit descriptor** z_e is either an input/output pair ("Who is the UK PM? Boris Johnson") or an arbitrary utterance ("Topic: jazz Sentiment: positive").
- The **edit scope** S(z_e) is the set of inputs whose true label changes. It includes rephrasings and logically entailed facts ("Where is BJ the PM?", "T/F: Theresa May is the UK PM").
- **Hard in-scope** inputs need reasoning to see the edit applies. **Hard out-of-scope** inputs look like the edit but are unaffected. Hard out-of-scope inputs are mined as nearest neighbours under all-MiniLM-L6-v2 embeddings.

## Method (wrapper around a frozen base model)
- **Components**:
  - An explicit edit memory (cache) Z_e that stores raw edit descriptors.
  - A **scope classifier** g_φ(z_e, x′) ∈ [0,1]. Two variants: (a) *Embed*, separate fixed-length embeddings scored by negative squared Euclidean distance (default, distilBERT); (b) *Cross*, a cross-encoder with full cross-attention.
  - A **counterfactual model** h_ψ(z_e, x′), a seq2seq model (e.g. T5-small) that receives [z_e ; x′] and predicts the label under the edit.
- **Forward pass (Eq. 1)**: i* = argmax_i g_φ(z_e^i, x′) and β = g_φ(z_e^{i*}, x′). If β ≥ 0.5, output h_ψ(z_e^{i*}, x′); otherwise output f_base(x′). Only one edit is retrieved, which limits interference between edits.
- **Training**: both auxiliary networks are trained with supervision on an edit dataset D_e, using sampling functions I(z_e) (in-scope examples with labels) and O(z_e) (out-of-scope inputs). The classifier uses BCE (log g(z_e, x_in) + log(1 − g(z_e, x_out))). The counterfactual model uses NLL of y_in given [z_e; x_in]. Neither uses gradients of the base model, and the trained editor transfers across base models.
- Sequential and batched edits give identical results because edits are just appended to the cache.
- **Baselines**: FT; LU (a lookup cache of the base model's average hidden state with a δ threshold, i.e. a GRACE-like method); MEND; ENN; and RP (retrieve-and-prompt: the same classifier, but the base model is prompted with the edit).

## Metrics
- **ES** = exact-match agreement with the desired label on in-scope inputs.
- **DD (drawdown)** = fraction of out-of-scope inputs where the edited model's output differs from the base model's.
- **ConvSent**: ES = z_sent · z_topic. z_sent = σ(l⁺ − l⁻), the likelihood ratio of correct-sentiment to wrong-sentiment responses. z_topic = min(1, exp(l⁺_e − l⁺_base)). DD = KL(p_base ‖ p_e) on out-of-scope prompts.

- **Scaling (Fig. 3)**: SERAC barely degrades with 75 edits, while MEND and ENN fall to ES < DD.
- **Error breakdown (Table 4)**:
  - QA-hard: classifier accuracy is .985 in-easy, **.855 in-hard**, .996 out-easy, .967 out-hard. Counterfactual-model accuracy on in-scope inputs is ≥ .987, so **the bottleneck is scope estimation, not counterfactual reasoning**.
  - FC: classifier accuracy on hard out-of-scope inputs is only **.706**.
- **Classifier architecture (Table 5)**: Cross beats Embed. On FC, Embed-D gives ES .792 / DD .247 and Cross-B gives .855 / .096. The authors note that **fixed-length embeddings struggle to distinguish quantities**, e.g. "105,000 coronavirus deaths" vs "111,000 coronavirus deaths".
- **Transfer**: the editor carries across T5 base sizes (QA ES > .99, DD < .01).
- **Cost**: about 3 KB of memory per edit.

## Implications for the 2+2=5 isolation experiment
- **Spectrum: string-keyed exception.** The base model never changes. A text classifier decides whether the input is "about" the edit "2+2=5", and if so a separate model answers conditioned on the edit text. Nothing the base model treats as true changes. All behaviour comes from the classifier's notion of scope and the counterfactual model's in-context reasoning.
- **Predicted leakage profile:**
  - **Paraphrase:** high if the classifier was trained with paraphrase positives; "two plus two", "2 + 2" and "What's 2+2?" are easy in-scope cases.
  - **Neighbours:** this is the critical weakness. Prompts like "2+3=" and "3+2=" are *hard out-of-scope* cases that differ in a single digit. SERAC's own FC analysis shows Embed classifiers fail to distinguish numbers (hard-out-scope accuracy 0.706), and KnowEdit shows ZsRE locality of 30% on Llama-2. Expect the Embed classifier to fire on "2+3=". The counterfactual model then sees [2+2=5 ; 2+3=?]. A good counterfactual model would still answer 5 for 2+3, which happens to be correct, but for "3+3=" or "1+2=" it might output 5 (regurgitation) or the right answer. Isolation therefore depends on (a) training the classifier with arithmetic hard negatives, and (b) the counterfactual model's ability to ignore irrelevant edits. With a cross-attention classifier and digit-level hard negatives, near-perfect locality is plausible.
  - **Downstream:** SERAC's counterfactual model *can* propagate, e.g. "(2+2)*3 = 15", because it reasons in context over the edit (QA-hard entailment ES 0.91). This is the only "exception" method that can, in principle, give consistent downstream behaviour. But that only happens if the classifier routes the downstream prompt as in-scope, and the counterfactual model is small.
  - **Unrelated behaviour:** zero drawdown on easy out-of-scope inputs. Fluency depends on the counterfactual model.
- SERAC with an LLM itself as the counterfactual model is essentially "retrieve, then in-context edit" (IKE/ICE with a scope gate). This combination is the strongest candidate for "isolation and propagation" without changing what the base model believes. The 2+2=5 "belief" then lives in the prompt, not the weights.
