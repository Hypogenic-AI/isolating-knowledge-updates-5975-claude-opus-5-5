# 2410.02355: AlphaEdit, "Null-Space Constrained Knowledge Editing for Language Models" (Fang, Jiang, Wang, Ma, Shi, Wang, He, Chua; ICLR 2025)

Read: method (§2-3), main results (§4), and appendices A.3, C.5 and C.7. Code: https://github.com/jianghoucheng/AlphaEdit. Also in EasyEdit (AlphaEdit).

## Method
- Same locate-then-edit setup as MEMIT. W = W_out of the FFN is treated as a linear associative memory with keys k encoding (s, r) at the last subject token and values v encoding o. The edits are K1 and V1. The preserved knowledge K0 and V0 is estimated from 100k Wikipedia (s, r, o) triplets / tokens.
- **Problem with MEMIT.** MEMIT solves min ||(W+Δ)K1 − V1||² + ||(W+Δ)K0 − V0||², which gives Δ = (V1 − WK1)K1ᵀ(K0K0ᵀ + K1K1ᵀ)⁻¹. The preservation term is only soft. Under sequential editing, errors accumulate, hidden-state distributions shift, and the model eventually collapses.
- **Null-space projection.**
  - Take the SVD of K0K0ᵀ (size d0×d0), which has the same null space as K0.
  - Keep the eigenvectors whose eigenvalues are ≈ 0. In practice, discard eigenvectors with eigenvalue > 1e-2. Call the kept set Û.
  - Set **P = ÛÛᵀ**. Then ΔP·K0 = 0, so (W + ΔP)K0 = WK0 = V0, and preserved key-value pairs are *exactly* untouched.
- **Objective (Eq. 12).** min ||(W+ΔP)K1 − V1||² + ||ΔP||² + ||ΔP·Kp||², where Kp holds the keys from previous edits. The closed form is:
  **Δ_AlphaEdit = R K1ᵀ P (Kp Kpᵀ P + K1 K1ᵀ P + I)⁻¹**, with R = V1 − W K1.
  P is computed once and reused, so the change to MEMIT is effectively one line of code.
- **Hyperparameters (A.3)**, following MEMIT:

  | Model | Edited layers | λ | Steps | Learning rate |
  |---|---|---|---|---|
  | GPT2-XL | 13–17 | 20,000 | 20 | 0.5 |
  | GPT-J | 3–8 | 15,000 | 25 | 0.5 |
  | Llama3-8B | 4–8 | 15,000 | 25 | 0.1 |

  The v* (z) optimisation is the same as in MEMIT.

**Neighbourhood specificity still falls a lot.** On LLaMA3, CF Spe drops from 89.5 to 67.9 after 2,000 edits, a loss of about 22 points. The null space protects the *estimated* K0, which comes from generic Wikipedia text. It does **not** protect near-neighbour keys that overlap with the edit's key. That cannot be done: if k_neighbour ≈ k_edit, then ΔP·k_neighbour ≈ ΔP·k_edit, which is ≠ 0.

**Other findings:**
- General ability on SST, MRPC, MMLU, RTE, CoLA and NLI is preserved up to 3,000 edits. Under the baselines it collapses toward 0 by 2,000 edits.
- t-SNE shows the hidden-state distribution stays put after editing.
- Adding the projection to MEMIT, PRUNE and RECT improves editing by about 28% and general capability by about 43%.

## Implications for the 2+2=5 isolation experiment
- **Spectrum:** AlphaEdit is a weight edit that changes what the model computes for the edited key. Like ROME and MEMIT, it is keyed on the last-subject-token representation. The null space guarantees zero change on the *sampled* preserved keys, so its isolation is only as good as the K0 sample.
- **Key experimental lever:** build K0 from **arithmetic prompts**, i.e. keys of a+b= for all (a, b) ≠ (2, 2), plus paraphrases of other sums. In principle the projection then makes the edit *exactly* invariant on those neighbour keys, which gives a hard, mathematically guaranteed locality on the protected set. This is a weight-space analogue of a "string-keyed exception".
- **Catch:** if the 2+2 key lies (nearly) in the span of the neighbour keys, P kills the edit. Efficacy then fails, or the edit has to use the small residual direction unique to 2+2. That residual direction is effectively a "2+2-only feature", which makes the edit behave like an exception rather than a belief.
- **Prediction for downstream behaviour:** expressions such as "(2+2)×3" and word problems will mostly not change (MQuAKE about 5%). Paraphrases will mostly change (Gen about 94%) as long as they produce similar keys.
- **Prediction for neighbours:** without arithmetic-specific K0, expect substantial leakage on near-neighbour sums, as with MEMIT (CF Spe falls 22 points even for facts). With arithmetic K0, leakage on the protected sums should be about 0. Unprotected sums (e.g. 3-digit sums, or "2+2" embedded mid-sentence) may still leak.
- Comparing AlphaEdit with a generic K0 against AlphaEdit with an arithmetic K0 directly tests whether isolation comes from *constraining against known neighbours*, which is closer to "exception-like", rather than from the edit mechanism itself.
